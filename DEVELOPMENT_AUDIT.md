# Sleek Colors Development Audit

Date: 2026-08-27

This file records the starting implementation baseline for the MVP in `PRD.md`.
It supports Phase 1 of `DEVELOPMENT_PLAN.md` and should be updated when the
project foundation changes materially.

## Product Baseline

- Product: static frontend palette discovery website.
- Runtime content model: static TypeScript or JSON data only.
- Explicitly excluded from version 1: backend, database, CMS, admin panel,
  authentication, payments, and user-generated content.
- Required launch content: at least 100 curated general palettes and at least
  30 website color combinations.
- Required routes:
  - `/`
  - `/palettes`
  - `/website-colors`
  - `/palette/[slug]`
  - `/preview/[palette-slug]`
  - `/category/[slug]`
  - `/search`
  - `/about`
  - `/random`

## Local Next.js Documentation Read

The following local docs were read before framework-specific planning:

- `node_modules/next/dist/docs/01-app/01-getting-started/02-project-structure.md`
- `node_modules/next/dist/docs/01-app/01-getting-started/03-layouts-and-pages.md`
- `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/src-folder.md`
- `node_modules/next/dist/docs/01-app/03-api-reference/05-config/02-typescript.md`

Key implications:

- The app should continue using App Router route folders and `page.tsx` files.
- A route is public only when a `page.tsx` or `route.ts` file exists.
- `src/app` is supported, but root `app` takes precedence if both exist.
- If moving to `src/`, the root `app` folder must be moved, not duplicated.
- Static params and metadata can be handled in App Router route files later.
- Global helpers such as `PageProps` and `LayoutProps` are generated by
  `next dev`, `next build`, or `next typegen`.

## Target Structure

Use this target structure during Phase 1 and Phase 2 unless a later decision
changes it:

```text
src/
  app/
    page.tsx
    layout.tsx
    globals.css
    palettes/
      page.tsx
    website-colors/
      page.tsx
    palette/
      [slug]/
        page.tsx
    preview/
      [palette-slug]/
        page.tsx
    category/
      [slug]/
        page.tsx
    search/
      page.tsx
    about/
      page.tsx
    random/
      page.tsx
    not-found.tsx
  components/
    layout/
    palette/
    search/
    ui/
  data/
    palettes/
    taxonomy/
  lib/
    clipboard/
    colors/
    seo/
    validation/
  types/
```

Notes:

- Keep route files focused on routing, metadata, and page composition.
- Keep static content behind data access helpers so UI does not depend on the
  physical data-file layout.
- Prefer Server Components for static rendering; introduce Client Components
  only for clipboard, filters, preview controls, and other browser-only state.
- Keep `public/` at the project root per Next.js `src` folder guidance.
- If `src/` is adopted, update the TypeScript alias from `@/*` to `./src/*`.

## Baseline Verification Results

Verified on 2026-08-27:

- `npm.cmd run lint`: passed.
- `npx.cmd tsc --noEmit`: passed.
- `npm.cmd run build`: failed before application compilation completed because
  `next/font/google` could not fetch Geist and Geist Mono from
  `fonts.googleapis.com` in the current environment.

Build implication:

- Replace generated Google font usage with approved local fonts or system font
  tokens before treating production builds as a reliable baseline command.
