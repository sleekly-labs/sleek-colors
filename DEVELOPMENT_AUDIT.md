Key implications:

- The app should continue using App Router route folders and `page.tsx` files.
- A route is public only when a `page.tsx` or `route.ts` file exists.
- `src/app` is supported, but root `app` takes precedence if both exist.
- If moving to `src/`, the root `app` folder must be moved, not duplicated.
- Static params and metadata can be handled in App Router route files later.
- Global helpers such as `PageProps` and `LayoutProps` are generated by
  `next dev`, `next build`, or `next typegen`.
- `params` and `searchParams` are promises in page and layout props; route
  code should await them or use the generated `PageProps` and `LayoutProps`
  helpers.
- Pages and layouts are Server Components by default; browser APIs, clipboard,
  search controls, and preview state should stay in small Client Components.
- `metadata` and `generateMetadata` are Server Component APIs; do not manually
  add `<head>` tags in the root layout.
- Use `generateStaticParams` for static palette, preview, and category detail
  routes once static data exists.
- Keep global CSS and Tailwind imports in the root layout entry; use Tailwind
  utilities for most component styling and CSS Modules only for scoped cases
  that utilities cannot cover cleanly.
- `next/font/google` self-hosts fonts for browsers after build, but the build
  still needs network access to Google Fonts. Use local fonts or system font
  tokens if offline builds must pass.

```text
    random/
      page.tsx
    not-found.tsx
  components/
    layout/
    palette/
    search/
    ui/
  data/
    palettes/
    taxonomy/
  lib/
    clipboard/
    colors/
    seo/
    validation/
  types/
```

Notes:

- Keep route files focused on routing, metadata, and page composition.
- Keep static content behind data access helpers so UI does not depend on the
  physical data-file layout.
- Prefer Server Components for static rendering; introduce Client Components
  only for clipboard, filters, preview controls, and other browser-only state.
- Keep `public/` at the project root per Next.js `src` folder guidance.
- `src/` is now adopted, and the TypeScript alias maps `@/*` to `./src/*`.
